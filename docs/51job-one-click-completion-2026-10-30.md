# 51job 人才管理与人才望远镜一键处理

日期：2026-10-30；版本：1.8.87。

## 这次问题的原因

1. 人才管理同步在读取详情和硬性条件判定前，按“本地已存在”跳过候选人。江踊此前从平台“合适”状态直接导入；再次出现在“待处理”时因此漏筛。
2. 本地把 51job 原始 JSON 当作简历正文显示，造成“解析内容”混杂平台字段。
3. 一键沟通仍依赖手工关联旧详情链接和二次点数确认。
4. 人才望远镜的旧标签页停在加载骨架，职位组件与候选人列表没有出现；软件从这个标签页读取时只能返回“无结果”。
5. 望远镜此前只有只读筛选预览，没有按平台人才 ID 执行“不感兴趣”与 Hi聊的逐人动作。

## 本轮实现

- “待处理”中的人选即使已在本地，也重新读取详情并按当前项目硬性条件筛选；明确不符者在平台标记“不合适”，取得成功回执后归档本地旧简历。资料缺失或超时只记录原因并补读。合适、面试、待定仍直接导入。
- 51job 简历显示为求职意向、个人优势、工作经历、项目经验、教育经历、证书六节；原始 JSON 独立保存用于硬性条件判定。
- 专属库一键打招呼按稳定人才 ID 查找 51job 详情；只处理未联系、未淘汰且无已知硬性条件失败的人。发送前核对项目绑定职位与点数，单人上限 100 点，本批上限由 HR 设置。逐人记录发送、跳过及回执不明；回执不明不重复首次 Hi聊。
- 首次 Hi聊使用平台默认招呼语。项目级文案在首次成功后作为第二条消息发送；失败者保持“已联系”，文案单独标记待重试，并提供独立重试入口。重试前平台脚本检查聊天记录中是否已有相同内容。
- 望远镜一键 Hi聊只从本轮合格名单中选择已在本地专属库的人。望远镜“不感兴趣”另设独立按钮；按账号、职位、人才 ID 与卡片上的 `no_interested_{人才ID}` 唯一定位。选择不到学历不匹配原因时选“其他原因”，填写`不匹配`。
- 望远镜旧页只有加载骨架时，在后台刷新该标签一次再读取。已实测刷新后读到 20 个职位和当前职位的 100 名候选人；未触发平台发送或拒绝。

## 执行和回执规则

- 平台动作前先核验当前账号、职位和候选人是否仍在名单。操作意图先写台账，成功回执才标记完成；结果不明保留“待核查”，再次点击不会重复操作。
- 望远镜未推荐名单在平台页面默认折叠；操作代码只在目标人才属于该分组时展开，再按其稳定 ID 定位按钮。
- 本轮没有对真实候选人执行 Hi聊或“不感兴趣”。平台原因弹窗、真实发送回执与江踊的归档结果仍须在使用时逐人观察；代码不会把未确认回执记作成功。
