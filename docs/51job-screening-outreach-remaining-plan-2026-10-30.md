# 51job 筛选与一键操作：本轮状态及后续方案

日期：2026-10-30。本文记录本轮已完成的代码改动和仍需实施、验证的部分；不把尚未取得平台回执的动作记为完成。

## 问题原因

1. 人才管理同步先按“本地已有简历”跳过，再读取平台详情及判定条件。江踊的旧简历曾从“合适”状态直接入库；现在即使再次出现在 51job“待处理”，旧跳过逻辑也让学历不符未被重新筛查。
2. 51job 原始详情 JSON 直接作为简历正文显示，所以解析内容混杂大量平台字段。
3. 旧简历没有有效详情链接时，打招呼流程要求 HR 手工关联；打招呼另有点数确认弹窗，与现在的一键操作要求冲突。
4. 人才望远镜当前已登录浏览器标签处于骨架加载状态：页面标题和菜单可读，但候选人列表组件、职位标签数据均未出现，因此目录返回“未能解析出职位列表”。现有望远镜代码只生成只读筛选预览，没有实现“Hi聊”或“不感兴趣”的逐人平台动作；界面不能把只读结果解释为已操作。

## 本轮已修改

- 人才管理“待处理”即使本地已有简历，也逐人读取详情、重新判定项目硬性条件。明确不符者执行平台“不合适”；取得成功回执后归档旧本地记录。详情超时或缺失只保留失败记录，不自动拒绝。
- “合适、面试、待定”保持直接导入的既定规则。
- 51job 正文整理为求职意向、个人优势、工作经历、项目经验、教育经历、证书六节；原始资料另存，继续用于硬性条件判定。
- 单人打招呼改为自动按项目绑定职位和稳定人才 ID 查找详情链接，省去手工粘贴与批次点数确认；点数超过单次 100 点上限时阻止发送，并在后端再次检查已知硬性条件失败。
- 隐藏筛选窗口中的“待核实”名单标签，保留旧记录和失败原因供后续补读。

## 尚需完成

### 人才望远镜平台动作

1. 在已登录、已选职位的真实望远镜页面，按平台人才 ID 唯一定位卡片；不得仅凭姓名点选。
2. 增加两个独立按钮：“一键 Hi聊”只作用于本地专属库中、未联系未淘汰且无已知硬性条件失败者；“一键不感兴趣”只作用于本轮明确不符者。直接执行，不再弹逐人核对名单。
3. 每人操作前校验企业账号、职位和人才 ID。Hi聊读取点数并检查项目限额；取得平台回执后才记“已联系”。不感兴趣没有“学历不匹配”时选“其他原因”，填入`不匹配`，确认平台状态后才记成功。回执不明时只查状态，不重复点击。
4. 在批次界面实时显示每人成功、失败和未确认回执，支持安全重试；已完成平台动作的人必须去重。

### 一键打招呼与补读

1. 将目前简历详情页的单人“一键打招呼”扩展为专属库批量入口，显示预计及实际点数、成功和失败数量，遵守项目总点数限额。
2. 旧记录自动找链接可能需要逐页扫描四类平台名单。按账号、职位、人才 ID、投递 ID 精确绑定；找不到时跳过并显示原因。新入库记录优先保存平台详情链接，避免重复搜索。
3. 对详情超时或资料缺失者安排补读；仅当取得明确不符证据时才执行平台拒绝。历史“待核实”保留审计，重新扫描时按新规则处理。

## 验证门槛

- 使用江踊所在真实职位复扫：确认待处理中的大专学历判为不符，平台拒绝成功后本地旧档案归档；失败时不得误报成功。
- 在真实望远镜页面验证职位发现、卡片 ID 定位、原因弹窗和回执，再开放两个操作按钮。当前页面读取不到职位，尚未完成此项现场验证。
- 检查重复运行、登录失效、弹窗结构变化、点数不足和回执不明时均不重复扣点或拒绝。
