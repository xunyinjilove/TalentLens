# 51job 人才管理四类同步：实施与验收

日期：2026-10-29

## 最终规则

| 51job 状态 | 岗位硬性条件 | 本地阶段 | 平台动作 |
| --- | --- | --- | --- |
| 待处理 | 逐项核验 | 合格者进入「待处理」 | 明确不符且资料完整者标记「不合适」；资料不明者留待核实，不点击 |
| 合适 | 不再次筛选 | 待联系 | 无 |
| 面试 | 不再次筛选 | 初面 | 无 |
| 待定 | 不再次筛选 | 待处理 | 无 |

四类均逐人读取完整简历；读取失败或资料缺失者留在待核实，并显示原因。已入库人选不重复建档，已有 HR 推进的阶段不被回退。招聘阶段原名「新入库」在界面改为「待处理」。独立的「扫描当前项目所有待处理人选」入口已移除。

## 当前实现

1. 四类同步共用同一职位绑定与平台账号核验。待处理先读完整详情，再以项目已保存的硬性条件判定；另外三类读取后直接建档。
2. 待处理明确不符的人逐人提交平台「不合适」并保存回执；已有成功记录不重复点击，回执不明时保留待核实状态。为避免平台列表在拒绝后移位造成漏扫，待处理页从最后一页向前处理。
3. 平台拒绝操作仍受项目「自动标记不合适」和「HR 合规授权确认」两项设置约束；未启用时继续同步与入库，未执行的平台操作在待核实列表明确标注原因。
4. AI 分析完成后，来自平台「待处理／待定」的简历仍停在本地「待处理」；平台「合适／面试」对应的本地阶段保持不变。

## 验收步骤

1. 在测试账号下选择一个绑定职位，设置并保存硬性条件与自动标记授权。
2. 分别找一名待处理合格、待处理明确不符、待处理资料缺失、合适、面试和待定人选，运行四类同步。
3. 检查本地阶段分别为待处理、未入库、待核实、待联系、初面、待处理；不符者在 51job 进入不合适并有逐人回执。
4. 同一职位再次运行，确认已入库者不重复建档，平台已处理者不重复点击。
5. 在待处理有多页的职位上验证末页到首页的遍历，确认没有因操作后页码移动而漏人。

## 现场验证边界

自动化测试覆盖本地阶段映射和分析后的阶段保持；51job 真实页面的拒绝弹窗、原因选项、回执以及分页移动需要在已登录的测试账号中现场验证。回执无法确认时保留待核实记录，不能将其记为成功，也不能盲目重复点击。
